# Local Review Against v1.9.4

Reviewed on 2026-10-04: local `1.9.6` worktree, including `82f8884`, CPU fix
`60944f5`, capabilities extraction and the follow-up fixes below. No remote
operations or device access. Physical-device validation remains outstanding.

## Resolved Findings

### P1: Media startup ignored a failed mandatory teardown patch

`c300x_media_bridge_start` now checks the guard before creating media sockets or
threads. Missing/unknown binaries and backup/write failures block PCMU startup,
and the specific error remains visible through video status. Ring receiver and
Home Call entry points cannot bypass an unsuccessful bridge startup.

Production-code regression tests exercise missing, forged and unwriteable
targets, corrupt backups and a patch that is installed but not active. They
assert no media sockets/threads, failed activation and preserved error detail.
Speex does not require this patch.

### P1: Already-PCMU backfill did not request activation

Patch application now propagates its `changed` flag to the codec action.
Codec status distinguishes `teardown_patch_installed` from
`teardown_patch_active`. A full hash of each matching `/proc/PID/exe` verifies
the loaded executable, which still refers to the original inode after an atomic
file replacement. Missing, unreadable or unpatched daemon images fail closed.

An installed but inactive patch requires a reboot even when both codec strings
are `pcmu`. The requirement is reconstructed from live process/file state after
agent restarts, without a persistent marker, timer or automatic startup reboot.
Media remains blocked until activation is verified. The HA select preserves
the pending state even when the codec itself does not change.

The local native test retains the original inode, applies the backfill, checks
that reapply is write-free and activation remains pending, then switches the
simulated process image to the patched inode. Only the last step clears the
requirement. Separate CLI invocations also retain the pending requirement.

### P1: Two integers were accepted as firmware identity

Native patching and the offline builder now require the complete allowlisted
source SHA-256 and exact size, then verify the complete patched SHA-256.
Backups must match the complete stock identity before patching or restoration.
Unknown, modified, mixed and truncated binaries cannot be patched; corrupt
backups cannot be restored. Flush/sync failures abort replacement.

The real local stock copy is 186,932 bytes. Roundtrip tests prove exactly six
changed bytes at the two intended words and byte-identical restoration.
Negative tests cover forged files with valid drain words, modifications outside
the patch ranges, partial patches, truncation and corrupted backups. Builder
tests also reject source/target aliases. No firmware bytes are stored in Git.

### Issue #56: Literal SIP-user presence was an unsupported blocker

The native self-test no longer equates a missing literal `c300x` database row
with broken on-demand video. Existing identity fallback remains unchanged;
HA-user presence, domain and routing checks still run. The row-presence flag
is exposed as non-sensitive diagnostic data only.

HA corrects the known 1.9.5 failure at the API contract boundary, using its
reported HA-user, identity and route flags. All must be explicitly true to
clear that failure; missing or inconsistent facts do not become success.
Readiness and Repairs consume the same corrected result, while the raw reply
remains available internally. No new polling, device writes or media control.

Native tests run the real identity/status parsers and self-test against local
read-only fixtures, including missing HA users, domain, accounts and routes.
HA tests cover clearing an existing false Repair without hiding route failures.
