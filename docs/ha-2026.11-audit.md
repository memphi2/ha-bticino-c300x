# Home Assistant 2026.11 and Marketplace Audit

Status: 1.9.9 compatibility audit, checked 2026-11-02. No device deployment.
Changes are forward preparation only: the validation targets stay
2026.7 and 2026.10. HA 2026.11 is not adopted as a supported validation target.

The earlier exploratory preview run used 2026.11.0b1 with requirements-dev.txt
in a separate virtual environment. Its results below are historical preview
evidence, not a promotion of the supported target or an active beta dependency.

## Compatibility and deadlines

| Change | Repository assessment | Action |
| --- | --- | --- |
| DeviceInfo becomes a dataclass in 2026.11 | Entity metadata used a dictionary and mutation | Use the public keyword constructor; keep unset firmware omitted |
| Explicit flow step_id required in 2027.5 | Direct form/menu/progress/external calls already supply it | Guard with an AST regression test |
| Config entry setup/unload/migrate return None in core | Custom integrations may still return bool without deprecation | Preserve the supported 2026.7 contract; no speculative rewrite |
| Listener plus reload flow helpers fails from 2026.12 | An update listener exists; reconfigure uses async_update_and_abort, not async_update_reload_and_abort | Preserve one reload owner; regression guard against reload helpers |
| RestoreStateData.last_states removed in 2026.11 | No use in integration code | No change |
| ha-md-list and ha-md-list-item removed | No use in bundled frontend | No change |
| Deprecated DeviceInfo defaults/via_device | No use in integration code | No change; avoid adding deprecated fields |
| New camera two-way audio capability | Requires real receive-audio support on the exact HA stream | Do not advertise it solely because the custom card supports talkback; validate the stream first |

## Marketplace readiness

- Same bticino_c300x domain, one integration per repository, existing HACS ZIP
  layout and generated agent bundle. No second card listing or domain migration.
- Add the documented security_safety.doorbells_intercoms manifest category.
- Keep hacs.json: Marketplace still consumes it. Retain HA 2026.7 minimum.
- Existing brand assets and English/German/French/Italian translations remain
  inside the integration package. Runtime user data must stay outside it.
- Document Settings > Marketplace for 2026.11+, HACS for older supported HA.
- Catalog admission and remote repository metadata are separate from local
  readiness. No catalog submission or remote settings change is performed here.
- The repository privacy gate intentionally rejects personal owner names in
  committed metadata. Keep the existing codeowners list unchanged; catalog
  owner requirements need an explicit policy decision, not a privacy bypass.

## LTS work

1. A future move to 2026.11 requires an explicit decision and a full test run
   against its final release. Keep the current target at 2026.10 meanwhile.
2. Keep minimum-HA tests, type checks, release ZIP checks, native ABI/stack gates,
   legal audit, SPDX validation and tag/commit-bound attestations.
3. Keep security updates independent of quarterly routine tooling updates.
4. Preserve push-driven operation: these changes add no C300X polling, writes,
   TLS initialization or native-agent changes. Agent 1.9.8 remains current.
5. Physical GUI/media/HTTPS validation and the PCMU reboot investigation remain
   independent gates; HA API compatibility does not prove a device fix.

## Local validation

- Full suites on HA 2026.10.0 and 2026.11.0b1: 2,230 passed, 2 skipped each.
- Targeted metadata, schema, packaging and forward-compatibility tests passed
  on HA 2026.7.0, 2026.10.0 and 2026.11.0b1.
- Strict typing passed for all 135 checked modules on all three HA versions.
- Real HA 2026.11 DeviceInfo dataclass probe and preview dependency check passed.
- Ruff, repository checks and legal/provenance audit passed. No native sources
  changed; no new firmware or hardware validation is claimed.
- A selected combination of existing event/camera/runtime tests exposed shared
  HA-stub state (issue_registry/dispatcher), although both complete suites pass.
  Test selection independence remains maintenance work, not a fixed product bug.
- Local security review: no added input handling, network operations, device
  writes or authentication bypass. Documentation/test exclusions in the old
  token gate retain rejection of forbidden APIs in runtime sources.

## Test tooling deprecation

AnyIO 4.14.1's automatically loaded pytest plugin imports CallSpec2, an alias
scheduled for removal in pytest 10. This is not an integration API warning.
The suite uses explicit asyncio.run calls, not AnyIO tests or fixtures, so
pytest disables that unused plugin with `-p no:anyio`. Runtime AnyIO remains
untouched; no warning filter, pytest monkeypatch or HA dependency override is
used. Future AnyIO-based tests would require revisiting that plugin policy.

Sources: https://docs.pytest.org/en/stable/deprecations.html and
https://anyio.readthedocs.io/en/latest/versionhistory.html
